# 개인 지식 포트폴리오 사이트 설계

## 1. 목표

개인 공부 기록을 공개하고, 축적된 지식과 실제 결과물을 함께 보여주는 포트폴리오 사이트를 만든다. 첫 화면은 방문자가 사용자의 관심 분야와 결과물을 빠르게 이해할 수 있는 포트폴리오로 구성하고, 내부는 Obsidian처럼 노트 사이의 연결을 탐색할 수 있는 지식 저장소로 구성한다.

첫 버전의 성공 기준은 다음과 같다.

- Markdown 파일만 추가해 새 공부 노트를 공개할 수 있다.
- 방문자가 검색, 태그, 위키 링크, 백링크, 관계 그래프로 지식을 탐색할 수 있다.
- 프로젝트와 관련 공부 노트가 자연스럽게 연결된다.
- 예시 프로필과 콘텐츠를 설정 파일 및 Markdown 파일만 수정해 실제 정보로 교체할 수 있다.
- 데스크톱과 모바일에서 읽기 쉽고 포트폴리오로 공유하기에 완성도 있는 화면을 제공한다.

## 2. 선택한 접근

정적 Markdown 지식 정원 방식으로 구현한다. 빌드 시 Markdown을 HTML로 변환하고, 공개 노트 전체를 분석해 위키 링크, 백링크, 검색 색인, 그래프 데이터를 생성한다.

이 방식은 별도 데이터베이스와 관리자 서버가 필요 없고, 페이지 로딩과 검색엔진 노출에 유리하며, Obsidian에서 작성한 Markdown 파일을 그대로 활용하려는 요구와 가장 잘 맞는다.

브라우저에서 Markdown을 즉석 변환하는 방식은 초기 구현은 단순하지만 초기 로딩과 공유 미리보기가 약해 제외한다. 로그인, 데이터베이스, 웹 에디터를 포함하는 풀스택 방식은 현재 필요한 범위를 넘어가므로 제외한다.

## 3. 정보 구조

### 홈 `/`

- 큰 소개 문장과 현재 관심 분야
- 현재 공부 중인 주제
- 대표 프로젝트
- 최근 공개 노트
- 전체 노트와 프로젝트로 이어지는 명확한 탐색 링크

### 노트 목록 `/notes`

- 전체 공개 노트
- 제목, 본문, 태그 기반 검색
- 주제와 태그 필터
- 최근 수정일 또는 발행일 기준 정렬
- 결과가 없을 때의 빈 상태

### 노트 상세 `/notes/[slug]`

- Markdown 본문
- 제목, 요약, 날짜, 태그 등의 메타데이터
- 자동 생성 목차
- `[[위키 링크]]`
- 연결된 노트와 이 노트를 참조하는 백링크
- 관련 노트의 짧은 미리보기

### 지식 그래프 `/graph`

- 공개 노트 전체의 관계 그래프
- 노드 드래그, 확대, 축소
- 노드 선택 시 제목, 요약, 직접 연결된 노트 표시
- 선택한 노트 상세 페이지로 이동

### 프로젝트 `/projects`

- 프로젝트 목록과 상세 설명
- 사용 기술, 결과, 데모 링크, 저장소 링크
- 프로젝트에 연결된 공부 노트

### 소개 `/about`

- 자기소개
- 기술 관심사
- 연락처와 외부 프로필 링크

## 4. 화면 구조

데스크톱 노트 화면은 세 영역으로 구성한다.

- 왼쪽: 주요 페이지, 노트 분류, 최근 노트 탐색
- 중앙: 읽기 콘텐츠
- 오른쪽: 현재 문서 목차, 관련 노트, 백링크

모바일에서는 읽기 중심의 단일 열을 사용한다. 주요 탐색은 슬라이드 메뉴로 제공하고, 목차와 백링크는 본문 아래 또는 접을 수 있는 패널로 이동한다.

홈과 프로젝트 화면은 포트폴리오 성격을 강조하되, 사이트 전체의 탐색 체계와 시각 언어를 공유한다.

## 5. 시각 디자인

승인된 방향은 “에디토리얼 지식 정원”이다.

- 아이보리 계열의 종이색 배경
- 짙은 먹색 본문
- 링크와 핵심 강조에 제한적으로 사용하는 보라색
- 제목용 세리프와 본문·UI용 산세리프 조합
- 카드보다 여백, 가는 선, 작은 메타 정보로 만드는 계층
- 큰 소개 문장과 편집물처럼 배열한 최근 노트·프로젝트
- 밝은 테마 기본, 시스템 설정과 수동 전환을 모두 지원하는 다크 모드
- 짧고 절제된 페이지 전환과 등장 효과
- `prefers-reduced-motion`을 존중하는 모션 처리

## 6. 콘텐츠 모델

### 사이트 설정

단일 설정 모듈에서 다음 내용을 관리한다.

- 이름
- 사이트 제목
- 한 줄 소개
- 긴 소개
- 관심 분야
- 이메일 또는 연락 링크
- GitHub 등 외부 프로필
- 기본 SEO 설명

첫 버전에는 자연스러운 예시 값을 넣고, 사용자가 한 파일에서 교체할 수 있게 한다.

### 노트

노트는 `content/notes/*.md`에 저장한다. frontmatter는 다음 필드를 지원한다.

- `title`: 필수 제목
- `slug`: 선택 주소. 없으면 파일명에서 생성
- `summary`: 목록과 미리보기에 사용할 요약
- `publishedAt`: 발행일
- `updatedAt`: 수정일
- `tags`: 태그 배열
- `topic`: 대표 주제
- `draft`: 비공개 초안 여부

`draft: true`인 노트는 페이지, 목록, 검색 색인, 백링크, 그래프에서 모두 제외한다.

### 프로젝트

프로젝트는 `content/projects/*.md`에 저장한다. 다음 정보를 지원한다.

- 제목과 요약
- 상태와 기간
- 사용 기술
- 문제, 접근, 결과
- 데모 및 저장소 링크
- 관련 노트
- 대표 프로젝트 여부

## 7. 연결과 데이터 흐름

1. 빌드가 사이트 설정, 노트, 프로젝트 Markdown을 읽는다.
2. frontmatter를 검증하고 공개 콘텐츠만 선택한다.
3. 제목과 slug 색인을 만든다.
4. 본문의 `[[노트 제목]]`과 명시적 관련 노트를 해석한다.
5. 정방향 링크에서 백링크를 계산한다.
6. 같은 연결 정보로 전체 그래프의 노드와 간선을 생성한다.
7. 공개 콘텐츠만 포함한 검색 색인을 생성한다.
8. 각 경로의 정적 페이지와 공유 메타데이터를 출력한다.

내부 데이터 생성 로직은 Markdown 렌더링 및 UI와 분리한다. 링크 분석, 백링크 생성, 그래프 생성, 검색 문서 생성은 각각 독립적으로 테스트할 수 있는 모듈로 구성한다.

## 8. 상호작용

- `Ctrl+K` 또는 `Cmd+K`로 전역 검색을 연다.
- 검색 결과는 제목, 요약, 본문, 태그를 대상으로 즉시 갱신한다.
- 위키 링크에 마우스를 올리거나 키보드로 초점을 이동하면 연결 노트의 제목과 요약을 보여준다.
- 그래프는 포인터와 터치로 이동 및 확대할 수 있다.
- 그래프 노드를 선택하면 해당 노트와 직접 연결된 노트를 강조한다.
- 모든 주요 기능은 키보드로 접근할 수 있고, 포커스 위치가 시각적으로 분명해야 한다.

## 9. 오류와 빈 상태

- 존재하지 않는 위키 링크는 본문에서 깨진 링크로 구분해 표시한다.
- 깨진 위키 링크는 빌드를 중단하지 않지만 검증 결과에 경고로 출력한다.
- 필수 frontmatter 누락, 잘못된 필드 형식, 중복 slug는 잘못된 페이지 연결을 만들 수 있으므로 빌드를 실패시킨다.
- 노트가 없을 때, 프로젝트가 없을 때, 검색 결과가 없을 때 각각 안내 문구와 다음 행동을 제공한다.
- 그래프 데이터가 비어 있거나 렌더링하지 못해도 노트 목록과 링크 탐색은 계속 사용할 수 있어야 한다.

## 10. 예시 콘텐츠

실제 개인 정보가 아직 없으므로 개발, 데이터, 생산성 분야를 중심으로 예시 프로필, 노트, 프로젝트를 제공한다. 예시 콘텐츠는 기능을 시연하기 위한 것으로, 별도 코드 수정 없이 설정 파일과 Markdown 파일을 교체해 제거할 수 있어야 한다.

예시 노트는 위키 링크, 태그, 백링크, 목차, 코드 블록을 실제로 보여줄 만큼 서로 연결한다. 예시 프로젝트는 관련 노트가 프로젝트의 학습 과정으로 자연스럽게 이어지는 구조를 보여준다.

## 11. 접근성 및 반응형 기준

- 데스크톱, 태블릿, 모바일에서 주요 콘텐츠가 잘리거나 겹치지 않는다.
- 키보드만으로 탐색, 검색, 테마 전환, 그래프 상세 열기가 가능하다.
- 텍스트와 인터랙티브 요소는 충분한 색상 대비를 가진다.
- 의미 있는 HTML 구조와 명확한 레이블을 사용한다.
- 애니메이션 감소 설정을 존중한다.

## 12. 검증 기준

- 홈, 노트 목록, 노트 상세, 그래프, 프로젝트, 소개 페이지 렌더링 검증
- 위키 링크 변환, 백링크 계산, 그래프 간선 생성 검증
- 비공개 초안이 모든 공개 출력에서 제외되는지 검증
- 검색 색인에 공개 콘텐츠만 포함되는지 검증
- 중복 slug와 잘못된 frontmatter가 빌드를 실패시키는지 검증
- 깨진 위키 링크가 경고로 보고되며 빌드는 계속되는지 검증
- 내부 링크 유효성 검사
- 데스크톱과 모바일의 시각 검토
- 프로덕션 빌드 및 배포 환경에서 최종 확인

## 13. 첫 버전에서 제외하는 범위

- 웹 관리자 화면과 웹 기반 글 편집
- 사용자 계정과 로그인
- 데이터베이스
- 댓글, 좋아요, 팔로우 기능
- 방문자 분석 대시보드
- 여러 작성자를 위한 권한 관리
- Obsidian 저장소와 원격 양방향 자동 동기화

Markdown 파일을 사이트 저장소에 추가해 다시 빌드하는 흐름을 첫 버전의 공식 발행 방식으로 사용한다.
